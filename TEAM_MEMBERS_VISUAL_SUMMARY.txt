API ENDPOINTS
================================================================================

1. GET /api/coordinator/eligible-team-members/<project_id>
   ├─ Request: None (uses session user_id)
   ├─ Response: {
   │   "employees": [
   │     {"id": 12, "username": "David", "email": "david@..."},
   │     {"id": 13, "username": "Emma", "email": "emma@..."}
   │   ],
   │   "count": 2
   │ }
   └─ Purpose: Load employee list when modal opens

2. POST /api/coordinator/add-team-members/<project_id>
   ├─ Request: { "user_ids": [12, 13, 14] }
   ├─ Response: {
   │   "message": "Successfully added 3 team member(s) to project",
   │   "added_count": 3
   │ }
   └─ Purpose: Save selected members to database

3. GET /api/coordinator/project-team-members/<project_id>
   ├─ Purpose: Get current team members (optional)
   └─ Response: List of current team members

4. DELETE /api/coordinator/remove-team-member/<project_id>/<user_id>
   ├─ Purpose: Remove a member (optional)
   └─ Response: Success message


VALIDATION RULES
================================================================================

SELECTION VALIDATION (Client-side):
  ✓ Can select: 1-3 members
  ✓ 4th checkbox: Auto-unchecks
  ✓ Error message: "Maximum 3 team members can be selected"
  ✓ Submit button: Enabled at 1+ selection

SUBMISSION VALIDATION (Server-side):
  ✓ User authenticated: Check session
  ✓ User is coordinator: Check project_coordinator_id
  ✓ All users valid: Check user_ids exist
  ✓ All users in team: Check parent_user_id = coordinator_id
  ✓ Not exceeding limit: Check len(user_ids) <= 3
  ✓ No duplicates: UNIQUE(project_id, user_id) enforced
